# Algorithm chart: text tasks, implementation and comparison

Research mapping: 2026-10-03. This document covers all seventeen chart entries. Each family now has an implemented route in the C# comparison code. **The expanded implementations are pending measured run reports; implementation does not establish accuracy, runtime, or a deployed replacement.** The application uses .NET 10 / ML.NET 5.0.0; the scratch neural experiments use TorchSharp-cpu 0.107.0 / LibTorch CPU 2.10.0 and are separate from built-in ML.NET trainers.

## Tasks and evidence

The six Romanian TimeBank tasks classify supplied EVENT class/tense, TIMEX type, and directed TLINK/SLINK/ALINK endpoints. Existing labels retain `provided_annotation/adjudication_unknown`. They are conditional targets, not independent human gold or an evaluation of mention discovery. The English/Romanian TYM annotations derive from one parallel Tash Aw work; they cannot provide a source-disjoint literary test by splitting their rows.

Raw books have no semantic labels. Clustering, projection and reconstruction can measure geometry, coverage and computational cost; classification accuracy is **not applicable** to those experiments. The linear-regression experiment fits one 0/1 class-indicator target per observed training class and selects the largest regression score. This is an explicit classification adaptation, not ordinal encoding of nominal labels or a numeric calendar prediction.

**Status vocabulary:** existing = prior executed capability; implemented, pending measurement = saved implementation without a verified expanded run report yet; documented future = a possible alternative outside the present run; N/A = the requested metric/task has no suitable target. The seventeen rows below have implementations; optional pretrained alternatives remain future work. Current status is about this project, not a claim that an algorithm is impossible elsewhere.

## A fair fixed comparison

1. **Keep the same rows and folds.** The existing TimeBank protocol joins documents sharing exact Unicode/whitespace-normalized task/language/input strings before creating three seed-42 folds: 157 documents become 50 components. These are duplicate-input components, not proof of independent works or identical ML.NET feature vectors. Near duplicates and shared news events remain possible.

2. **Pair representation and trainer.** Use the same three document-component folds for whole-text and structured trials. Native/custom vector classifiers use fold-fitted ML.NET text features, with separate source/target/context/signal channels in structured mode. Neural models use their own bounded word vocabulary and encoding on those same rows; their representation differs. Fit vocabularies, transforms, label maps, normalizers, PCA and token dictionaries on training rows only. Omit an empty channel using training inputs only.

3. **Freeze configuration before the new scores.** Serialize trainer options, seed, thread count, iteration/tree/epoch limits, sampling, sequence limits and hardware. Prescribe values for each algorithm; 100 iterations, 100 trees and 100 epochs are not equal computational budgets. Use the same declared processor allocation where APIs permit it and record exceptions/native parallelism.

4. **Keep adaptations visible.** OVA adds one binary model per observed class, or one 0/1 regression for the linear-regression adaptation. Report probability versus margin/regression decisions and calibrator fitting. Naive Bayes's binary-presence interpretation changes effective features. Fixed feature caps, token caps, PCA or sampled subsets need their own identifiers and coverage counts.

5. **Preserve rare labels and failures.** Report pooled accuracy, fixed-inventory macro F1, per-class support/confusion and labels absent from training folds. Record timeout, missing dependency, failed fit and nonapplicable targets explicitly; never replace them with zero accuracy or quietly remove a difficult task.

6. **Interpret selection honestly.** The expanded algorithm search follows inspection of earlier whole-text/structured diagnostics. Fixed settings make this run reproducible, but selection remains retrospective and exploratory. There is no untouched model-selection holdout or independent adjudicated literary test. Improvements need replication on frozen independent works before a generalization claim.

## Time, performance and accuracy summary contract

Every chart family must appear in the final summary, including `implemented_pending_measurement`, `failed` or `not_applicable` metric states. A result should identify algorithm variant, task/language, representation, rows/components, parameter/seed budget, status and report path. This document records implemented routes; expanded quality/runtime measurements await their run reports. The earlier grouped report contains executed SDCA/L-BFGS/structured diagnostics only.

| Experiment type | Time/performance to measure | Quality to report |
| --- | --- | --- |
| Conditional classifier | Featurizer fit, trainer fit, transformation/scoring time, row count and throughput; distinguish cold model load from warm inference; record peak process memory/model bytes if measured | Accuracy, macro F1, class support; not end-to-end span/graph or book accuracy |
| Regression class-indicator adaptation | Feature fit/transform plus all per-class regression fitting/scoring; number of regressions and rows | Categorical accuracy/macro F1 after argmax; not MAE/RMSE for calendar values or calibrated probabilities |
| Clustering | Preparation/projection/fit time, distance computations, memory, sample size and cluster/noise counts | Explicit geometric metrics and stability; semantic accuracy N/A |
| PCA/autoencoder | Projection/training/reconstruction time, dimensions, memory and held-out rows | Defined reconstruction/energy error and downstream diagnostics; classifier accuracy N/A by itself |

Report measured seconds and ms/row with their denominator; end-to-end timing includes feature work while trainer-only timing does not. Warm up serving separately, then use equal batch sizes and report repeated latency distributions if collected. One elapsed training run or a component test duration is not a P95 serving measurement. The geometric metrics of separately fitted language/representation spaces need not be directly comparable.

## Neural and package boundaries

The four compact classifiers and numeric autoencoder are implemented as scratch training in C# using TorchSharp-cpu 0.107.0 / LibTorch CPU 2.10.0. The classifier budget defaults to five epochs, batch 32, Adam learning rate 0.001 and cross entropy on one CPU thread; the autoencoder uses the same optimizer/batch budget with MSE. There is no Python application runtime, pretrained-weight claim or historical-model reproduction. Executed measurements remain pending. Tiny models and short fixed budgets do not establish a family's best achievable quality.

Neural text tokenization uses NFC/invariant lowercase and Unicode letters, marks and digits, preserving internal apostrophes/hyphens. The training-only vocabulary contains at most 2,048 IDs including padding and unknown. Structured mode prefixes **every word** with its role, for example `SourceMention-arrived` and `TargetMention-left`; internal-hyphen tokenization preserves those distinct identities, including in the MLP bag of words. Endpoint mentions and signal come before source/target context. This preserves declared roles for retained in-vocabulary tokens; it does not preserve within-channel order in the MLP or make the representation identical to ML.NET's separate feature blocks.

Every neural text model retains only the first 64 encoded words; tokenless input becomes one unknown token, preventing an all-padding sequence. Role-specific tokens consume more vocabulary entries, and unseen/pruned words collapse to unknown. Long mentions or contexts can still be truncated despite endpoint-first ordering. Report vocabulary/truncation coverage when measured; no complete-context or full-book comprehension claim follows from this encoding. These synthetic channel sequences are conditional task inputs, not a forced chronological story order.

Its inspected source uses `EnglishRobertaTokenizer` and an external model download path, so Romanian coverage, exact tokenizer behavior, available weights, licensing, package/native-runtime compatibility and hashes must be checked before adoption.
